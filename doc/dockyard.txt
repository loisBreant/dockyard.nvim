1. INTRODUCTION                                        *dockyard-introduction*

Dockyard is a Docker workspace inside Neovim: a dashboard of containers,
images, networks and volumes, live logs (LogLens), shells and a file browser
inside containers, and clickable actions in compose files and Dockerfiles.

This is the loisBreant/dockyard.nvim fork of emrearmagan/dockyard.nvim.

==============================================================================
2. REQUIREMENTS                                        *dockyard-requirements*

- Neovim 0.10 or later
- the `docker` CLI in `$PATH` (`docker compose` or `docker-compose` for the
  compose actions)
- optional: toggleterm.nvim for shells (a native terminal is used without
  it), baleia.nvim for ANSI colours in logs, telescope.nvim for
  `:Telescope dockyard`

Run `:checkhealth dockyard` to check the setup.

==============================================================================
3. SETUP                                                      *dockyard-setup*

Install it and you are done; with lazy.nvim: >lua
  { "loisBreant/dockyard.nvim" }
<
No `setup()` call and no lazy-loading rules are needed: the plugin only loads
its code when a command is used, a compose file or a Dockerfile is opened, or
a `dockyard://` buffer is edited.

To change options, call `require("dockyard").setup({ ... })` (with lazy.nvim,
`opts = { ... }`). See |dockyard-config|.

4. COMMANDS                                                *dockyard-commands*

                                                                   *:Dockyard*
:Dockyard [{strategy}]
    Open the dashboard. {strategy} is one of `current`, `split`, `vsplit`,
    `tab`, `float` (aliases: `edit`, `horizontal`, `vertical`, `panel`).
    Without it, the modifier decides (|:tab|, |:vertical|, |:horizontal|,
    |:botright|, |:topleft|), else `display.open_strategy`.

:Dockyard pick                                              *:Dockyard-pick*
    Pick a container, then an action. See |dockyard-picker|.

:Dockyard files {container} [{path}]                       *:Dockyard-files*
    Browse {container}'s filesystem at {path} (default `/`).

:Dockyard logs {container}                                  *:Dockyard-logs*
    Open LogLens for {container}.

:Dockyard build                                            *:Dockyard-build*
    Build the image of the current Dockerfile, tagged after its directory.

:[range]Dockyard run                                         *:Dockyard-run*
    `docker compose up -d --force-recreate` for every service of the current
    or nearby compose file, or only the services in [range].

:Dockyard service [{action}]                             *:Dockyard-service*
    Act on the compose service under the cursor: `run` (default), `stop`,
    `restart`, `build`, `logs`, `shell`, or `open` (its first published port
    in the browser).


:Dockyard compose [{action}]                             *:Dockyard-compose*
    Open the compose options menu (|dockyard-compose-options|) for the
    current compose file, or the one in the working directory. {action} is
    what <CR> runs: `up` (default), `down`, `build`, `pull`, `stop`,
    `restart`.

:Dockyard jobs                                              *:Dockyard-jobs*
    Open the dashboard on the Jobs view (|dockyard-jobs|).

:Dockyard job [{id}|last]                                    *:Dockyard-job*
    Open the whole output of a job; `last` (default) is the most recent.

:Dockyard rerun [{id}|last]                                *:Dockyard-rerun*
    Run a job again.

                                                            *dockyard-aliases*
The older commands still work: `:DockyardFloat` (`open float`),
`:DockyardFull` (`open tab`), `:DockyardPick`, `:DockyardBuild`,
`:DockyardRun`, `:DockyardService`, `:DockyardFiles`, `:DockyardLogs`.

                                                           *dockyard-mappings*
Dockyard creates no global mappings. Bind the <Plug> mappings you want
(normal mode): >lua
  vim.keymap.set("n", "<leader>dd", "<Plug>(dockyard-open)")
<
  *<Plug>(dockyard-open)*             |:Dockyard|
  *<Plug>(dockyard-float)*            `:Dockyard float`
  *<Plug>(dockyard-pick)*             |:Dockyard-pick|
  *<Plug>(dockyard-build)*            |:Dockyard-build|
  *<Plug>(dockyard-run)*              |:Dockyard-run| for every service
  *<Plug>(dockyard-service-run)*      |:Dockyard-service| with that action,
  *<Plug>(dockyard-service-stop)*     on the service under the cursor
  *<Plug>(dockyard-service-restart)*
  *<Plug>(dockyard-service-build)*
  *<Plug>(dockyard-service-logs)*
  *<Plug>(dockyard-service-shell)*
  *<Plug>(dockyard-service-open)*
  *<Plug>(dockyard-compose)*          |:Dockyard-compose|
  *<Plug>(dockyard-jobs)*             |:Dockyard-jobs|
  *<Plug>(dockyard-job-last)*         `:Dockyard job last`

5. DASHBOARD                                              *dockyard-dashboard*

`<Tab>` / `<S-Tab>` (or `]` / `[`) switch between the views listed in
`display.views`.
Press `g?` in any Dockyard buffer for the bindings of the current view.

Common keys:
  `g?`      help                 `R`       refresh
  `q`       close                `<CR>`    expand / collapse
  `K`       inspect popup        `p`       detail panel

Containers view:
  `s`       start / stop         `x`       stop
  `r`       restart              `d`       remove
  `T`       shell                `L`       logs (|dockyard-loglens|)
  `f`       file browser         `o`       open a published port
  `F`       filter               `C`       clear the filter
  `P`       project scope on / off (|dockyard-scope|)

Images view: `d` remove, `P` prune. Networks and volumes views: `d` remove.
Jobs view: `<CR>` `K` open the output, `r` run again, `x` cancel, `y` copy
the command, `D` forget the finished jobs (|dockyard-jobs|).

Every key can be changed or disabled in `keymaps` (|dockyard-config|).

6. PROJECT SCOPE AND FILTER                                   *dockyard-scope*

`P` shows only the containers of the project Neovim works on. The project is
the git root of Neovim's working directory, or the directory itself. A
container belongs to it when its Docker Compose project was started from
inside it, or from a parent directory (Neovim opened in a subdirectory).
Containers started with a plain `docker run` have no project.

With `display.project_scope = "auto"` (the default) the dashboard opens in
this mode when the project root has a compose file. `true` and `false` force
a mode. The picker (|dockyard-picker|) follows the same scope.

                                                             *dockyard-filter*
`F` asks for a text and keeps the containers whose name, image, status,
ports or compose project contain it, ignoring case. `C` clears it. Scope and
filter combine; the header shows both with their counts.

7. COMPOSE ACTIONS                                          *dockyard-compose*

In `docker-compose.yml`, `compose.yaml` and their `compose.*.yml` variants,
each service shows its state and clickable actions at the end of its line,
and `services:` shows the project-wide ones:

  services:   ▶▶ Run all  ■ Stop all  ⟳ Build all  ▼ Down
    api:   ● healthy  ↻ Restart  ■ Stop  ≡ Logs   Shell  ↗ :8080  ⟳ Build
    db:   ○ exited  ▶ Run

- `▶ Run` / `▶▶ Run all`   `docker compose up -d`, with the options of the
                           project (|dockyard-compose-options|); the default
                           keeps `--force-recreate`
- `■ Stop`, `↻ Restart`, `⟳ Build`, `▼ Down`   the matching compose command
- `≡ Logs`                 LogLens on the service's container
- ` Shell`                a shell in it
- `↗ :PORT`                `http://localhost:PORT` in the browser

`⟳ Build` only appears for services with a `build:` section. The state
follows the healthcheck and refreshes while a service is starting. Actions
save the file first. Clicks elsewhere on the line behave as usual;
|:Dockyard-service| offers the same actions from the keyboard.

The `services:` line also has `⚙ Options`, with what differs from the
defaults next to it (`debug +build`), and services that have `profiles:` show
a `[profile]` chip.

                                                   *dockyard-compose-options*
`⚙ Options`, |:Dockyard-compose| or `<Plug>(dockyard-compose)` open a menu:

  Profiles        the profiles of the file (asked to `docker compose config
                  --profiles`, read from the file when that fails), and
                  `all profiles (*)`
  Saved           `--force-recreate` `--build` `--pull` `--no-deps` `--wait`
                  `--remove-orphans`: remembered for the project
  This run only   `-v` `--rmi` `-V`: never remembered

`<Space>` ticks a box, `<CR>` runs the action, `d` `b` `p` `s` `r` run `down`,
`build`, `pull`, `stop`, `restart`, `q` closes. The last line is the exact
command. Profiles and saved flags live in `stdpath("data")` under
`dockyard/projects.json`, one entry per compose file, and are used by every
button, so `down`, `stop` and `restart` see the active profiles too. `down`
with `-v` or `--rmi` asks first.

`compose_lens.enabled = false` turns these actions off, and the Dockerfile
ones too.

==============================================================================
8. DOCKERFILE ACTIONS                                    *dockyard-dockerfile*

A `Dockerfile` (also `Dockerfile.*`, `*.Dockerfile`, `*.dockerfile`) gets
two buttons on its first `FROM` line:

- `⟳ Build {tag}`   `docker build`, tagged after the directory
- `▶ Build & Run`   build, then `docker run --rm -it -P {tag}` in a terminal
                    split, publishing the exposed ports

==============================================================================
9. CONTAINER PICKER                                          *dockyard-picker*

`:Telescope dockyard` fuzzy-finds containers, running ones first, with a
`docker inspect` preview. `<CR>` opens the action menu. Direct keys:

  `<C-l>` logs            `<C-t>` shell           `<C-f>` files
  `<C-o>` open port       `<C-s>` start / stop    `<C-r>` restart
  `<C-a>` every container, ignoring the project scope

|:Dockyard-pick| offers the same through |vim.ui.select()|, with or without
Telescope.

==============================================================================
10. FILE BROWSER                                              *dockyard-files*

|:Dockyard-files|, or `f` on a container, lists a directory of the container:

  `<CR>` `l`   open file / enter directory
  `-` `h`      parent directory
  `s`          find files by name (glob or plain text) into the |quickfix|
  `S`          search file contents into the |quickfix|
  `a`          create a file, or a directory when the name ends with `/`
  `r`          rename              `d`   delete
  `c` / `x`    copy / cut, then `p` pastes into the current directory
  `D`          download to the host
  `U`          upload from the host
  `y`          yank the path       `gh`  toggle hidden files
  `R`          refresh             `q`   close
  `g?`         help

                                                            *dockyard-buffers*
Container files open as `dockyard://{container}/{path}` buffers. `:w` writes
them back into the container and keeps the file's owner and permissions.
`:edit dockyard://{container}/{path}` works from anywhere; a directory path
opens the browser.

==============================================================================
11. LOGLENS                                                 *dockyard-loglens*

`L` on a container (or |:Dockyard-logs|) streams its logs:

  `f`   follow on / off       `r`   raw / parsed
  `/`   filter                `c`   clear the filter
  `<Tab>` / `<S-Tab>`  switch source
  `<CR>` `K`   entry details  `q`   close

Log sources, parsers and highlight rules are configured per container in
`loglens.containers`; see the README for the full format.

12. CONFIGURATION                                            *dockyard-config*

Options go through `require("dockyard").setup()`, which is optional and
only merges them over these defaults: >lua
  require("dockyard").setup({
    display = {
      -- "containers", "compose", "images", "networks", "volumes", "jobs"
      views = { "containers", "images", "networks", "volumes", "jobs" },
      open_strategy = "tab",   -- current|split|vsplit|tab|float
      project_scope = "auto",  -- true | false | "auto"
    },
    compose_lens = { enabled = true },
    compose = {
      defaults = {             -- projects without saved preferences
        force_recreate = true, build = false, no_deps = false,
        wait = false, remove_orphans = false,
        pull = false,          -- false | "always" | "missing" | "never"
      },
    },
    jobs = {
      history = 50,
      notice = { close_after = 3000 },
    },
    loglens = { containers = {} },
    keymaps = {
      ui = {
        help = "g?", close = "q", refresh = "R",
        next_view = { "<Tab>", "]" }, prev_view = { "<S-Tab>", "[" },
        toggle_node = "<CR>", open_details = "K", open_panel = "p",
      },
      containers = {
        toggle_start_stop = "s", stop = "x", restart = "r", remove = "d",
        open_terminal = "T", open_logs = "L", open_files = "f",
        open_port = "o", filter = "F", clear_filter = "C",
        toggle_project_scope = "P",
      },
      images = { remove = "d", prune = "P" },
      networks = { remove = "d" },
      volumes = { remove = "d" },
      jobs = {
        open_output = "<CR>", rerun = "r", cancel = "x", clear = "D",
        copy_command = "y",
      },
      loglens = {
        close = "q", toggle_follow = "f", toggle_raw = "r",
        filter = "/", clear_filter = "c",
        next_source = "<Tab>", prev_source = "<S-Tab>",
        open_detail = { "<CR>", "K" }, help = "g?",
      },
    },
  })
<
A keymap set to `false` is disabled; a list adds aliases.
`loglens.containers` and `loglens.default_highlights` configure log sources
and highlight rules; see the README for their format. |:checkhealth| reports
options with a wrong type and unknown ones.

==============================================================================
13. JOBS                                                       *dockyard-jobs*

Every command Dockyard runs is a job with its command line, status, duration
and whole output. A notice shows the command and the tail of the output; it
closes after a success (`jobs.notice.close_after`, in milliseconds, 0 keeps
it) and stays after a failure: |:Dockyard-job| `last` opens the output; once
the notice is focused, `<CR>` does too and `q` closes it.

The Jobs view lists them, newest first, up to `jobs.history` finished ones,
in memory only. Keys (`keymaps.jobs`):

  `<CR>` `K`   open the output     `r`   run again
  `x`          cancel              `y`   copy the command line
  `D`          forget the finished jobs

The output buffer (`dockyard-job://{id}`) follows a running job while the
cursor is on its last line; `q` closes it, `r` runs the job again, `x`
cancels it. The `User DockyardJobChanged` autocommand fires on every change,
with `data = { id = {job id} }`.

==============================================================================
14. HIGHLIGHTS                                           *dockyard-highlights*

The action buttons use:

  `DockyardLensRun`      run buttons
  `DockyardLensStop`     stop / down buttons
  `DockyardLensAction`   other buttons
  `DockyardLensMuted`    separators
  `DockyardCursorLine`   selected row in the dashboard
  `DockyardPorts`        port buttons
  `DockyardRunning`, `DockyardStopped`, `DockyardPending`,
  `DockyardRestarting`   service states

The groups are defined with `default = true`, so a colour scheme or your own
|:highlight| commands take precedence. They are set again after |ColorScheme|.
